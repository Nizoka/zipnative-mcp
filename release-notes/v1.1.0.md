# zipnative-mcp v1.1.0

<!-- GitHub Release title: v1.1.0 - zipnative 1.1.0 parity, canonicalize and merge, byte-range reads, supply-chain hardening -->

_Released 2026-10-18_

**Built on:** zipnative v1.1.0

The first minor release, on the engine's first minor. Every zipnative 1.1.0 feature an agent can use safely is reachable — two new tools (`canonicalize_zip`, `merge_zip`, 13 → 15 tools), byte-range reads of sandbox archives larger than memory, the Zip64 streaming opt-in, cancellation and progress, extended timestamps and Unix ids — and every 1.0.0 call keeps working: the live catalogue is a checked superset of the frozen 1.0.0 one, the default output of every existing tool is byte-identical for every valid input on a UTC host (39 of the 41 baseline samples unchanged; the other two quote the package version), and `compression.deterministic: true` bytes are unchanged on a UTC host (on another zone a pinned date now encodes in UTC — C1). `TOOL_API_VERSION` moves to 1.1.0 (new inputs, two new tools, one new wrapper code). The release also closes two ReDoS paths, a sandbox read race and the findings of an independent two-auditor release audit (see Audit), and brings the repository to the hardening level of pkinative-mcp 1.0.0: one gate, a docs verifier, a hardened four-job publish workflow and a guarded agent layer.

## Highlights

- **Reproducible from any archive** — `canonicalize_zip` rewrites a Gradle, Maven, `zip`, Explorer or 7-Zip archive into the engine's canonical deterministic form without recompressing a payload, idempotently, and reports the engine's own `analyzeDeterminism()` verdict on the result; `modify_zip` `canonical: {…}` does the same on a compaction; `inspect_zip` `determinismReport: true` names what would drift.
- **Merge without recompression** — `merge_zip` transplants the entries of up to 32 source archives (inline or sandbox files, each with its own filter) into one, every entry CRC- and size-checked first (an entry whose method has no codec here is refused under `verify: true`), encrypted entries refused, conflicts resolved by `onConflict` `error` | `first` | `last` with the drops reported.
- **Archives larger than memory** — `access: 'auto' | 'memory' | 'range'` on `inspect_zip`, `list_zip_entries` and `read_zip_entry`: a sandbox `zipPath` above the 1 GiB in-memory cap is opened with the engine's `openZipRange` over the file's own handle (never a URL); memory stays at the size of the central directory plus the entries read. `create_zip` stream entries take `zip64: true`, and `ZIPNATIVE_MCP_MAX_FILE_OUTPUT_BYTES` lets an operator write archives above 4 GiB into the sandbox.
- **Same bytes on every host** — every engine call runs with `dosTimeMode: 'utc'`: a pinned `create_zip` / `modify_zip` date encodes to the same DOS fields in Paris, Kiritimati and Anchorage, and `lastModified` reads back as the same instant. 1.0.0 used the host time zone while declaring those calls cacheable.
- **Long calls behave** — the MCP request's cancellation stops every tool whose work grows with its input (`verify_zip` excepted: the engine's `verifyZip` takes no signal; it honours a cancellation only before it starts) — nothing cached, partial output removed, and per the MCP cancellation rules the client receives no response; a `progressToken` gets strictly increasing, throttled `notifications/progress`.
- **Supply chain at the level of pkinative-mcp** — `scripts/gate.ts` is the single definition of green; every job starts with harden-runner (the macOS leg of the `os` job excepted, documented) and installs with `--ignore-scripts`; `publish.yml` is `verify` → `publish` → `attest` → `registry` (Trusted Publishing with provenance, the registry bytes compared with the packed tarball, SLSA build provenance for the tarball and the SBOM, the MCP registry entry published with a SHA-256-pinned `mcp-publisher`); CodeQL `security-extended`; committed rulesets.

## Security

- **fix(security):** `list_zip_entries` / `extract_zip` / `scan_zip_forward` globs are matched by a linear-time automaton instead of a backtracking regular expression (CWE-1333: `*a*a*a…` over a 2 000-character entry name took 3.5 s); globs are bounded at 1 024 characters and an inverted class range is `VALIDATION_ERROR` instead of an uncoded failure.
- **fix(security):** the dependency pattern of the governance policy scan (`draft_governance_issue`, `npm run verify:issue`) no longer backtracks (4 000 characters took 40 s); the draft's free-text fields are bounded at 16 384 characters; the test regex flagged by CodeQL `js/redos` (code-scanning alert 8) is unambiguous.
- **fix(security):** every sandbox read (`zipPath`, `sourcePath`, `resources/read`, the forward scanner, the cache) goes through one file handle: opened, `fstat`-ed, its real path proven inside the sandbox and bound to the handle by device and inode, then only the handle is read. A file swapped between the check and the read is `SECURITY_VIOLATION`; a file that grows or shrinks under the read is `IO_ERROR`.
- **fix(security):** `modify_zip` opens its input eagerly. The append path never re-reads the existing entries, so 1.0.0 re-emitted an archive with overlapping entries (the smuggling shape every other reader refuses) or a truncated local header unchecked; it is now refused with its `ZIP_*` code before any operation. Found by the new seeded fuzz suite.
- **fix(security):** an exception that is not a `ToolError` is `ENGINE_ERROR` with `_meta.error.data.errorClass: 'internal'` and a message stripped of absolute paths (1.0.0 returned an uncoded text).
- **fix(security):** `fields` paths refuse prototype segments (`__proto__`, `constructor`, `prototype`); the projection walks own properties only.
- **fix(security):** CLI and HTTP: `ZIPNATIVE_MCP_PORT` must be an integer in 1..65535 and `ZIPNATIVE_MCP_OUTPUT_DIR` an absolute path, or the server refuses to start; header, request and keep-alive timeouts and a header-count bound; `X-Content-Type-Options: nosniff` and `Cache-Control: no-store` on every response — the security headers are applied after the SDK's own, which set `no-cache, no-transform` on a legacy-era 200 (found by the final review, R-027; locked by `tests/http-hardening.test.ts`).
- **fix(deps):** `npm audit` reports 0 vulnerabilities on the full tree (vitest 4.1.11 for GHSA-82fw-gwwq-j7x9, js-yaml 4.3.2 by override, `@cyclonedx/cyclonedx-npm` and its unpatched `ip-address` / `http-cache-semantics` advisories removed — the SBOM is `npm sbom`).
- **ci(security):** least-privilege workflow permissions (CodeQL `security-events: write` on the job, `contents: write` only in the `attest` job of `publish.yml`), harden-runner on every job, `persist-credentials: false`, one SHA per action across the tree, dependency review with a licence allow-list, a weekly `npm audit`, `.npmrc` `ignore-scripts=true`.

## Changed

- **chore(deps):** zipnative ^1.1.0, `@modelcontextprotocol/server` ^2.3.1 (licence Apache-2.0 since 2.3.0), zod ^4.6.5; dev: vitest 4.1.11, typescript-eslint 8.71.1, tsx.
- **fix(engine):** dates are encoded and decoded in UTC (`dosTimeMode: 'utc'`); an offset-less date-time is the UTC wall clock (the DOS fields 1.0.0 wrote for it in every zone) — see C1.
- **fix(tool):** `verify_zip` counts by the engine's archive rule — an encrypted entry whose local header contradicts the central directory is now `failed` (C3).
- **chore(tool):** `inspect_zip` takes its determinism sub-checks from `analyzeDeterminism()`; the default verdict keeps the 1.0.0 formula, so no CI gate flips (C4).
- **chore(errors):** the local node:zlib error table is gone: the engine normalises corrupt deflate to `ZIP_DEFLATE_*` on every inflate tier, so `scan_zip_forward` reports `ZIP_DEFLATE_CORRUPT` / `ZIP_DEFLATE_TRUNCATED` where 1.0.0 surfaced `ZIP_DECOMPRESSION_FAILED` (C6).
- **fix(http):** the SDK request-body bound is raised to the documented 256 MiB (1.0.0 kept the SDK's 4 MiB default, so larger inline archives failed over HTTP); a 2026-07-28 request without the `MCP-Protocol-Version` header is answered 400 / -32020 by SDK 2.3 (C10).
- **chore(tooling):** the veraZIP core is re-vendored from zipnative 1.1.0 (`WF/DESCRIPTOR-WIDTH`, 23 check ids); the corpus grows to 43 archives (39 conformant, 4 negative canaries) with compact-canonical, canonicalised, pinned-date canonicalised, merged and Zip64-streamed entries; `vitest.config.ts` pins `TZ=UTC` and the forks pool.

## Audit

Before the release, two independent auditors (security, hardening, protocol and breaking changes; coverage, documentation truth, token economy and agent autonomy) audited the branch from `v1.0.0`, each claim reproduced with a command, and a third agent re-derived every finding (`.audit/1.1.0/`, git-ignored; the process is `.claude/skills/release-audit/`). 73 findings were stamped: 57 confirmed, 7 downgraded, 2 rejected, 7 duplicates — 0 blocker, 7 major, 33 minor, 24 note. Every confirmed or downgraded blocker / major / minor finding is fixed in this release with a lock test named after it (`tests/audit-v1.1.0.test.ts`, `tests/sandbox.test.ts` A-013, `tests/cli-stdio.test.ts` A-020, `tests/tools/workflows.test.ts` A-004 / A-009 / A-010) or a documentation fix; two are repository settings the maintainer applies (the `npm-publish` environment protection, the rulesets — `.github/drafts/pr-v1.1.0.md`); three engine root causes are reported upstream to zipnative (the `verifyZip` signal, the eager local-header check, a stale diagnostic doc path). No valid 1.0.0 call breaks: the 30 v1.0.0 examples replayed against the 1.1.0 build return the same shape (the byte differences on a non-UTC host are C1). A final independent review of the fixed branch (the shipped artefact, the fix commits, the blind spots the audit had left) closed with the slow tests above, the over-the-wire prototype-pollution probes — which showed that the MCP SDK removes a root-level `__proto__` key before the server sees it, so the documented `VALIDATION_ERROR` holds for nested keys and in-process calls only — `release-prepare` covering every release date, `Cache-Control: no-store` enforced on the legacy-era answers the SDK had relabelled (R-027), the head-before-body HTTP refusals proven on the built binary (`tests/http-shutdown.test.ts`), and `scripts/README.md`.

## Known limitations

- `canonicalize_zip` and `modify_zip` copy compressed payloads verbatim: a corrupt entry stays corrupt (run `verify_zip` first when integrity matters); `merge_zip` verifies every entry before the copy.
- Byte-range reads serve `inspect_zip`, `list_zip_entries` and `read_zip_entry`; `verify_zip`, `extract_zip`, `canonicalize_zip`, `merge_zip` and `modify_zip` still buffer the archive (1 GiB cap for a `zipPath`), because the engine accepts bytes only on those paths.
- No decryption (the engine labels AES / ZipCrypto entries and never decrypts in 1.x); no legacy name decoding input (`nameDecoder` stays unexposed); no remote archive — there is no network path, and none will be added.
- `verify_zip` cannot be interrupted once it has started: zipnative's `verifyZip` is synchronous and takes no signal (reported upstream to zipnative).
- An inline archive result carries the bytes twice (the embedded resource's `data:` URI and its `blob`, the 1.0.0 shape kept for compatibility); `outputMode: 'file'` returns a `resource_link` instead and is far cheaper in tokens.
- The seeded fuzz suite is a deterministic regression net, not coverage-guided fuzzing (OpenSSF Scorecard `Fuzzing` stays open).
- The level-1 extractors of the veraZIP gate are the runner image's; their versions are recorded in the job summary, not pinned by checksum.
